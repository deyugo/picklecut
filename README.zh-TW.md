# picklecut

**匹克球比賽影片：標記回合、剪去死球時間、疊上懂 side-out 計分的常駐計分板。一個工具做完。**

把手機錄的整場比賽丟進來，標記每一次發球與每一個回合，picklecut 會剪掉回合之間的死球時間，並疊上一個隨比賽進行更新的計分板——比分、發球隊伍與發球員編號（#1／#2）全都跟著走。產出一支緊湊、好看的成片。

改寫自桌球工具 ttcut；剪輯與渲染流程相同，計分引擎換成匹克球規則。

---

## 需求

- **Python 3.8 以上**
- **ffmpeg** —— 本工具不打包，請自行安裝

```bash
# macOS
brew install ffmpeg

# 確認字幕濾鏡存在（計分板需要它）
ffmpeg -filters | grep subtitles
```

Windows 請把 `ffmpeg.exe` 放在腳本旁邊，或用 `--ffmpeg` 指定資料夾。可從 [ffmpeg.org](https://ffmpeg.org/download.html) 取得。

顯卡可有可無。啟動時會偵測硬體編碼器（NVENC、Quick Sync、AMF、VideoToolbox），有能用的就自動採用——見「輸出設定」。

## 開始使用

```bash
python3 picklecut_v1_1.py
```

工具會啟動本機伺服器並打開瀏覽器。**僅綁定 `127.0.0.1`，外部網路連不進來。**

1. 按左上角 **載入影片**——或**直接把影片拖進視窗**（可立即開始標記；影格率會在 1 倍速播放時自動估測；瀏覽器基於安全不會透露拖入檔案的路徑，所以按渲染時會跳一次檔案對話框確認位置）。拖入 `.tags.json` 則直接讀入標記
2. 填兩隊名稱與首發隊伍；選擇雙打／單打與計分制；確認影格率
3. 播放影片。每次發球按 `S`，回合結束按 `A` 或 `B` 標記**贏下回合的一方**——得分還是換發由系統自動判定
4. 右側面板即時顯示比分、正式報分（例如 `5–3–2`）與剪輯統計
5. 按下製作成片。成品會出現在來源影片旁，檔名 `<原名>.cut.mp4`，旁邊還有 `<原名>.tags.json`（標記）與 `<原名>.score.txt`（比分紀錄）

> **重新整理瀏覽器會清掉標記。** 影片路徑與進行中的渲染會保留，但標記事件不會。長比賽記得中途按 **匯出 JSON**。

## 給不寫程式的人

三種免打指令的用法，由輕到重：

**雙擊啟動器**（就在本專案裡）：機器上裝好 Python 與 ffmpeg 之後，雙擊 `picklecut.bat`（Windows）或 `picklecut.command`（Mac）即啟動中文版；`picklecut_EN.bat` / `picklecut_EN.command` 啟動英文版。使用期間請保持主控台視窗開著——關掉視窗就等於關掉工具。Mac 第一次要先執行 `chmod +x picklecut.command`（或右鍵 → 打開）。

**獨立執行檔**（完全不用裝 Python）：執行 `build_exe.bat`（Windows）或 `build_exe.sh`（Mac）——需要先 `pip install pyinstaller` 一次——然後把 `dist/` 裡的執行檔連同一個放在同資料夾的 `ffmpeg` 一起分享出去，對方雙擊就能用。兩個注意事項：防毒軟體常把剛打包好的 PyInstaller 執行檔誤判成威脅並在打包過程中直接刪掉——打包前請先把專案資料夾加入防毒排除清單；另外各平台要各自打包（Mac 版要在 Mac 上打）。

**區網分享**：加 `--listen` 啟動，主控台會印出一個區網網址（例如 `http://192.168.1.20:8770/`），同一個 Wi-Fi 上的任何手機、筆電打開就能用——對方完全不用安裝任何東西。影片、檔案對話框與渲染都在主機這台電腦上。**`--listen` 會對整個網路開放介面，只在信任的網路使用。** 真正架在網際網路上的版本刻意不做：那代表要把好幾 GB 的比賽影片上傳到伺服器，正是本工具在地優先設計要避免的事。

## 時間軸與修正標記

播放列下方有一條 LosslessCut 式時間軸：**亮色＝保留、暗色＝剪掉、金色＝highlight 回合**、細線＝發球、白線＝播放位置。點任一處即可跳轉。標記或設定一變它就跟著更新，成片會保留哪些段落一目瞭然。

任何錯誤都不必從頭重標：

- **移動標記**：每個事件列都有 `⟲` 鈕，把該標記移到目前播放位置。
- **刪除標記**：`×` 鈕，同以往。
- **校正比分**：計分板下方的「校正」列在目前時間插入一筆校正——只填想改的欄位（局、分、發球方、發球員 #），之後的計分接著算。中途要手動設定局數也是用它。校正以 `adjust` 事件存進 JSON。
- **之後再繼續**：載入匯出的 `.tags.json`（按鈕或直接拖入），事件、字幕、highlight、校正、設定全部還原、照樣可改。

## Highlight

回合進行中（或剛結束時）按 `H` 標記。畫質旁邊的**輸出範圍**選單提供：**完整比賽**（預設）、**僅 Highlight**（只出被標記的回合，計分板照燒——檔名 `<原名>.highlights.mp4`）、或**完整＋Highlight**，一次依序渲染兩支檔案、共用同一條進度。命令列則用 `--highlights` 從標記 JSON 出精華。

## 字幕

在事件列表上方的字幕列輸入文字，按 **＋字幕**（或 Enter）：這行字會從目前播放位置起、以指定秒數（預設 3 秒）燒錄在成片底部置中。字幕以 `caption` 事件存進標記 JSON（`{"t": 12.4, "type": "caption", "text": "…", "dur": 3}`），會出現在事件列表裡、跟其他標記一樣可以刪除，且跨剪點自動重新對時——整段落在被剪掉區間裡的字幕會自動略過。

## 比分紀錄

每次渲染都會在成片旁多寫一份 `<原名>.score.txt`：各局結果（11–7、9–11……）、局數統計，以及逐分紀錄——原始影片時間、第幾局、由誰發球（雙打會標 `A#2`）、該回合誰贏、當時比分、換發，以及 highlight 回合的 ★。校正與手動換局也會列在裡面，所以這份紀錄可以解釋計分板上的每個數字。標題列的**匯出比分**鈕不渲染也能下載同一份文字；`--dry-run` 會在剪接表之後印出。

## 剪輯規則

回合結束到下一次發球之間是死球時間——撿球、換位、跟隊友對看一眼。picklecut 剪的就是這段。

| 設定 | 預設 | 作用 |
|---|---|---|
| 回合後保留 | 1.0 s | 回合結束後多留幾秒，讓球在畫面上彈完 |
| 發球前保留 | 0.3 s | 下次發球前多留一點，剪點才不突兀 |
| 最短剪點 | 2.0 s | 短於此秒數不剪，避免無意義跳接 |
| 重發也剪 | 關 | 開啟後，重發之間的死球時間也剪掉 |
| 重發後保留 | 1.5 s | 僅在上一項開啟時適用 |

## 計分規則

以下全部可在介面調整，並存進標記 JSON：

- **傳統計分（side-out，預設）**：只有發球方能得分。雙打每局由首發隊伍的第二發球員開局（即「**0-0-2**」開局）；發球方輸掉回合時，發球權從 #1 交給 #2，再輸就換發給對方。單打輸掉回合直接換發。一局只能在發球方贏下回合時結束。計分板以一顆（#1）或兩顆（#2）強調色圓點標示發球方，介面同步顯示三碼正式報分。
- **每球得分制**：每回合都得分，由勝方發下一球。（採通用規則；MLP 的 freeze 等特殊規定未實作。）
- **雙打／單打**切換
- **每局分數**——預設 11，賽會制可改 15 或 21
- **勝 2 分**（標準）或**封頂制**——先到封頂分即勝
- **起始局數**——一局一支影片、接續前面局數時用
- **讓分**——任一方可設起始分，可選每局套用或僅第一局
- **起始發球員編號**——首發選單旁的「#1／#2 · 接續」，給接續雙打局中段的影片用

計分只在 Python 實作一次，介面與成片渲染呼叫同一個函式，兩邊永遠不會不同調。

## 一場比賽分成多支影片

一場比賽錄成好幾個檔案時，各段分開剪、最後再接起來：

1. **第一支影片**：照常標記、渲染。順手匯出標記 JSON——下一段載入它，隊名、賽制、顏色都直接帶過去。
2. **第二支影片**：把**起始局數**設成影片開始時的局數。若從一局中間開始，把**讓分**設成當下比分、範圍選**僅第一局**，**首發**選當時發球的一方，並在旁邊選**發球員編號**（#1／#2）。計分板與報分就會無縫接續。
3. 每一段都用**相同的畫質設定**渲染，最後無損串接：

```bash
python3 picklecut_v1_1.py --join game1.cut.mp4 game2.cut.mp4 -o match.mp4
```

`--join` 是 stream copy——不重新編碼、零畫質損失——所以各段的解析度、影格率與編碼設定必須相同（同一台相機、用本工具同樣選項渲染就會相同）。

## 輸出設定

| 畫質 | 倍率 | CRF | preset | 說明 |
|---|---|---|---|---|
| `fast` | 0.70× | 21 | veryfast | 草稿，先確認剪點對不對 |
| `high` | 1.00× | 18 | medium | 預設；維持來源解析度 |
| `max` | 1.40× | 16 | slow | 強制軟體編碼——最慢也最好 |

影格率預設跟著片源。HDR 片源預設 tone-map 成 SDR。

**顯卡編碼。** 啟動時會用這個平台上 ffmpeg 提供的每個硬體編碼器實際試編幾格——Windows 是 NVENC（NVIDIA）、Quick Sync（Intel）、AMF（AMD），Mac 是 VideoToolbox——第一個真的能跑的就當預設編碼器。終端機會印出偵測結果，畫質旁的**編碼器**下拉選單也是同一個選擇（自動／各可用硬體編碼器／CPU `libx264`）。命令列 `--encoder` 可覆寫；`max` 畫質一律用 `libx264`。實際感受：獨立的 NVIDIA 或 AMD 顯卡在 1080p60 比 CPU 快好幾倍；Intel 內顯配上強的桌機 CPU 大致打平（主要是降低 CPU 負載），只有對上弱的筆電 CPU 才明顯快。硬體**解碼**（`--hwaccel`）只有 Mac 預設開；Windows 上 4K 反而常變慢，因為每一格都要複製回來疊計分板，除非量過有賺，否則不必開。

## 命令列

手上已有標記 JSON 時，可以跳過介面直接渲染：

```bash
# 基本
python3 picklecut_v1_1.py match.tags.json match.MOV

# 指定輸出路徑與畫質
python3 picklecut_v1_1.py match.tags.json match.MOV -o final.mp4 --quality max

# 只印剪點表不渲染，先檢查剪點
python3 picklecut_v1_1.py match.tags.json match.MOV --dry-run
```

## 標記 JSON 格式

匯出的檔案是純 JSON——可攜、可 diff、可手改。Mac 標記、Windows 渲染，同一個檔案通用。

```json
{
  "version": 3,
  "generator": "picklecut V1.1",
  "source": "IMG_1496.MOV",
  "fps": 30,
  "sport": "pickleball",
  "players": { "A": "A 隊", "B": "B 隊" },
  "firstServer": "A",
  "format": { "pointsPerGame": 11, "deuce": "standard", "cap": 12,
              "scoring": "sideout", "side": "doubles" },
  "start": {
    "games":  { "A": 0, "B": 0 },
    "points": { "A": 0, "B": 0 },
    "handicapScope": "every"
  },
  "pads": { "tail": 1.0, "lead": 0.3 },
  "scoreboard": { "accent": "#BFD730" },
  "events": [
    { "t": 12.400, "frame": 372, "type": "serve" },
    { "t": 15.000, "frame": 450, "type": "highlight" },
    { "t": 18.933, "frame": 568, "type": "point", "winner": "A" },
    { "t": 20.000, "frame": 600, "type": "caption", "text": "賽末點", "dur": 3 },
    { "t": 45.100, "frame": 1353, "type": "game" },
    { "t": 46.000, "frame": 1380, "type": "adjust", "games": { "A": 1 }, "server": "B", "serverNum": 2 }
  ]
}
```

事件共六種。影響剪接與計分的三種：`serve`、`point`（帶 `winner`——**贏下該回合**的一方，不論是否實際得分）、`game`。另外三種只是附帶、不影響剪接：`highlight`（把它所在的回合標進精華）、`caption`（`text` 與 `dur` 秒數，燒在底部置中、跨剪點自動對時）、`adjust`（比分校正：`games`、`points`、`server`、`serverNum` 任填，只覆寫有出現的欄位）。渲染成片旁也會寫出一份對應的 `.tags.json`。

## 疑難排解

**瀏覽器不顯示影片，但檔案本身沒問題**
來源大概是 HEVC。Chrome 無法預覽 HEVC；Safari 可以。在 Mac 上本來就建議用 Safari 標記——有原生 4K H.264 硬體解碼。

**macOS 警告 libass 找不到 PingFang 字型路徑**
無害，忽略即可。字型會在 AssetsV2 找到，計分板正常渲染。

**Windows 說缺 tkinter**
部分 Python 發行版不含 tkinter，檔案對話框打不開。改用命令列渲染，或安裝含 tkinter 的 Python。

**找不到 ffmpeg**
介面啟動時會提示。仍可標記與匯出 JSON，只是無法產出成片。安裝 ffmpeg 或用 `--ffmpeg` 指定後重新啟動。

**渲染很慢**
看終端機的「硬體編碼」那行（或介面的編碼器選單）。顯示「無」代表沒有硬體編碼器通過啟動測試，現在是 CPU 在做——`fast` 畫質是最快的 CPU 選項。若偵測到硬體編碼器卻還是慢，選單改選 CPU `libx264` 試試；CPU 夠強時 Intel 內顯不會比較快。Windows 上 `--hwaccel` 不要開。

**成片畫質比預期差**
若目標碼率低於片源，渲染前會印出警告與建議值。用 `--bitrate` 或 `--quality max` 覆寫。若片源本身碼率就低，畫質受限於錄影，這裡無能為力。

## 桌球（ttcut）

本專案源自的桌球工具也一併收在這裡，並升級為 **ttcut V2.4**：`ttcut_v2_4.py`（繁體中文）與 `ttcut_v2_4_EN.py`（英文），配好啟動器 `ttcut.bat` / `ttcut_EN.bat` / `.command`、共用 `build_exe` 打包腳本與 `--listen`。V2.4 之後兩個工具是同一份程式碼換上不同的計分引擎：所有與運動無關的功能——拖放、時間軸、字幕、highlight、比分校正、`--join`、顯卡偵測——兩邊都有。

不同之處：

- **計分引擎。** ttcut：兩球一換發、deuce（預設 10–10）後一球一換，到目標分且領先兩分或到封頂即結束一局。picklecut：發球得分制或每球得分制、單打／雙打、發球員編號、0-0-2 開局。桌球**雙打**：在 ttcut 切到「雙打」，計分板會標示一對裡輪到誰發（● 是先填的人、●● 是後填的人）；每次該隊接下發球權就換人，每局重新從 #1 開始。決勝局 5 分的接發對調不會自動處理，用校正列的「#」輸入。
- **計分板與介面。** 兩邊的計分板都有發球圓點欄。ttcut 只有單打／雙打切換——沒有計分制下拉、沒有報分。校正列可設局數、分數、發球方與（雙打時）第幾位；指定發球方時兩球一輪從該點重新起算。
- **用語與參數。** 「A／B 得分」而非「A／B 贏回合」、擦網重發而非重發（`--cut-lets` / `--let-tail`）、預設橘色強調色。
- **標記 JSON。** ttcut 寫 `version` 2，沒有 `sport`、`format.scoring`、`format.side`、`start.serverNum`。兩種格式**不可**互通：picklecut 會用發球得分制去解讀 ttcut 的檔案，ttcut 則忽略匹克球欄位。

## 其他球拍運動

整條流程中只有計分引擎與運動項目相關。羽球就是每球得分制、每局 21 分（用現有選項即可：每球得分 + 21 + 封頂 30）。網球與板式網球（padel）需要新的計分邏輯與盤數欄位——已規劃、尚未實作。見 `docs/2026-08-31-pickleball-adaptation-design.md`。
